# Jira 이슈 트래커 — 요구사항 명세서

## 1. 서비스 목적

Jira 프로젝트 링크를 등록해두면, 일/주/월 단위로 **전 기간 대비 이슈 상태가 어떻게 변화했는지**를 자동으로 집계·요약해서 보여주는 개인용 모니터링 서비스.

- 여러 Jira 프로젝트를 한 번 등록해두고 지속적으로 추적
- "어제/지난주/지난달과 비교해서 무엇이 바뀌었는가"에 집중 (단순 현재 스냅샷이 아니라 **변화(diff)** 가 핵심)
- 대시보드에서 한눈에 확인 + 필요 시 MS Teams로 리포트 발송

## 2. 전제 조건 (확정된 사항)

| 항목 | 결정 |
|---|---|
| Jira 종류 | Jira Cloud (`*.atlassian.net`) — API Token + Email 기본 인증 |
| 사용 범위 | 개인용 (멀티유저/권한 분리 불필요, 구조 단순화) |
| 리포트 채널 | ① 대시보드 내 확인 ② MS Teams (Incoming Webhook / Adaptive Card) |
| 디자인 톤 | 깔끔하면서 세련된 느낌 (미니멀 + 디테일 있는 인터랙션) |

## 3. 핵심 사용자 시나리오

1. 사용자가 추적할 Jira 에픽의 브라우저 링크(예: `https://team.atlassian.net/browse/PROJ-123`) + 계정 이메일 + API 토큰만 입력해 등록한다. 사이트 도메인/프로젝트 키/추적 대상(해당 에픽의 하위 이슈)은 링크에서 자동으로 파싱되고, 표시 이름은 에픽 요약으로 자동 채워진다.
2. 시스템이 주기적으로(예: 매일 정해진 시각) 해당 프로젝트의 이슈 데이터를 수집해 스냅샷으로 저장한다.
3. 오늘 스냅샷과 이전 스냅샷(전일/전주/전월)을 비교해 변경 사항을 계산한다.
4. 대시보드에서 프로젝트를 선택하고 일/주/월 단위를 전환하며 변화 현황을 확인한다.
5. 설정된 주기가 되면 MS Teams로 요약 리포트가 자동 발송된다.

## 4. 기능 요구사항

### 4.1 프로젝트 관리
- 등록: 프로젝트 이름 + Jira 에픽 링크만 입력 (사이트 도메인/프로젝트 키/추적 JQL은 링크에서 자동 파싱·생성)
  - 추적 JQL: `"Epic Link" = <에픽키> OR parent = <에픽키>` (클래식/팀 관리형 프로젝트 모두 커버)
  - 추적 규칙: **리프(최하위) 레벨만 추적**. 에픽 직속 이슈에 하위작업이 있으면 그 이슈는 제외하고 하위작업만 추적하고, 하위작업이 없는 에픽 직속 이슈는 그 자체를 추적 (하위작업 유무로 판단 — 이슈 타입 이름에 의존하지 않음)
  - 같은 Jira 프로젝트 안의 서로 다른 에픽을 각각 별도 프로젝트로 등록 가능 (사이트+프로젝트키+에픽키 조합 유니크)
  - 계정 이메일 + API 토큰: 최초 등록 시 한 번만 입력하면 앱 전역에 기억되어 이후 등록부터는 생략 가능 (다른 Jira 계정으로 등록하고 싶을 때만 폼에서 "다른 계정 사용"으로 펼쳐서 재입력 — 입력하는 순간 그 계정이 새 기본값으로 갱신됨)
- 수정: 사이트 URL/프로젝트 키/이메일/API 토큰/표시 이름/리포트 설정을 직접 입력하는 상세 폼 (에픽 링크 재입력을 통한 재파싱은 미지원)
- 삭제
- 등록된 프로젝트 목록 뷰 (카드 형태, 최근 변경 요약 미리보기)
- 프로젝트별 활성/비활성(추적 일시중지) 토글
- API 토큰 유효성 즉시 검증 (등록/수정 시 테스트 연결)

### 4.2 이슈 데이터 수집
- Jira REST API(`/rest/api/3/search` 등)로 이슈 조회 — 상태, 담당자, 우선순위, 마감일, 라벨, 이슈타입, 생성/수정일 수집
- 프로젝트별 커스텀 JQL 필터 지원 (예: 특정 스프린트/컴포넌트만 추적)
- 일 단위 스냅샷 저장 (diff 계산의 기준 데이터)
- Jira API rate limit 대응 (배치 조회, 재시도/백오프)

### 4.3 변경 사항 추적 (Diff 엔진)
- 상태 변경 이슈 목록 (예: `In Progress → Done`)
- 신규 생성된 이슈 / 삭제(또는 필터 이탈)된 이슈
- 완료 처리된 이슈 수 및 목록
- 마감일(Due Date) 임박·초과 이슈 하이라이트
- 담당자 변경 이력
- 일/주/월 단위로 동일한 diff 로직 재사용 (기준 시점만 달라짐)

### 4.4 대시보드
- 프로젝트 선택 + 기간 단위(일/주/월) 전환 UI
- 상태 분포 (도넛/바 차트), 처리 추이 (라인 차트), 변경 타임라인
- "오늘의 변경사항" 요약 카드 (신규 N건, 완료 N건, 지연 N건 등)
- 지연/마감 초과 이슈 별도 하이라이트 섹션
- 여러 프로젝트 간 비교 뷰 (선택)

### 4.5 리포트 자동 생성/발송
- 발송 주기 설정 (매일/매주/매월, 시각 지정)
- MS Teams Webhook 연동 — Adaptive Card 형식의 요약 리포트
- 리포트 내용: 기간 요약 + 상태 변경 상세 목록 + 지연 이슈 강조
- 프로젝트별 발송 on/off, 임계치 기반 즉시 알림(예: 지연 이슈 N건 이상 발생 시)

### 4.6 설정
- 스냅샷 수집 주기 설정 (기본 1일 1회, 수동 새로고침 지원)
- 데이터 보관 기간 설정 (예: 최근 6개월 스냅샷만 유지)
- Teams Webhook URL 관리

## 5. 비기능 요구사항

- **보안**: Jira API 토큰, Teams Webhook URL은 암호화 저장 (평문 노출 금지)
- **성능**: 다중 프로젝트 동시 수집 시에도 Jira rate limit 초과 없이 안정적으로 동작
- **데이터 정합성**: 스냅샷 수집 실패 시 이전 데이터 유지 + 실패 로그/재시도
- **UI/UX**: 미니멀하면서 디테일 있는 인터랙션 (마이크로 애니메이션, 다크모드 고려), 반응형
- **확장성**: 개인용으로 시작하지만 추후 멀티유저 전환 가능성을 염두에 둔 데이터 모델(단, 초기 구현은 단순하게)

## 6. 추가 기능 제안

우선순위 순으로 나열했습니다. 초기 MVP 이후 단계적으로 고려하면 좋을 항목들입니다.

**MVP 직후 고려**
- 이슈별 상세 히스토리 타임라인 (Jira changelog 활용)
- 담당자별 워크로드/처리 속도 통계
- 커스텀 JQL 저장 및 재사용

**중기**
- SLA/마감일 위반 추적 리포트
- 주간/월간 요약 코멘트 자동 생성 (LLM 활용한 자연어 요약)
- 리포트 PDF/Excel Export
- 프로젝트 그룹핑/태그 (예: "백엔드팀", "2026 Q3")

**장기**
- 프로젝트별 목표(완료율/속도) 설정 및 진행률 추적
- Teams 외 다른 채널(이메일 등) 확장
- 예측 분석 (현재 속도 기준 완료 예상일)

## 7. 기술 스택 (확정)

| 영역 | 선택 |
|---|---|
| Frontend | Next.js (App Router) + TypeScript + Tailwind CSS v4 + shadcn/ui |
| 차트 | Recharts (Tremor는 Tailwind v4의 CSS 기반 설정과 호환이 어려워 제외) |
| 데이터 페칭/캐싱 | TanStack Query |
| Backend | Next.js Route Handlers (풀스택 단일 프로젝트) |
| ORM | Prisma 7 (driver adapter 방식, `@prisma/adapter-pg` 사용) |
| DB | PostgreSQL — 로컬은 Postgres.app, 프로덕션은 Supabase (확정) |
| 스케줄링 | GitHub Actions 스케줄 워크플로우가 매시간 배포된 앱의 `/api/cron/sync` 호출 (Vercel Cron은 Hobby 플랜 하루 1회 제한으로 미채택) |
| 인증 | 미구현. Vercel Deployment Protection으로 배포 URL 노출을 선택적으로 제한 |
| 배포 | Vercel (완료, `main` 브랜치 push 시 자동 재배포) |
| 외부 연동 | Jira REST API v3, MS Teams Incoming Webhook (Adaptive Cards) |

Next.js 풀스택 구조를 택해 프론트/백엔드를 한 저장소로 관리하고, Vercel + Neon/Supabase 조합으로 별도 서버 운영 없이 배포한다. 개인용 서비스이므로 인증은 NextAuth 등 무거운 구조 대신 단일 비밀번호 세션으로 단순화한다.
